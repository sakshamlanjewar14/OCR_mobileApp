# Lead Gennie — MVP Build Guide

> Living build document. Update this file whenever the MVP behavior changes. Keep the product focused on reviewed lead capture and export.

The proposed React Native mobile extension and its free-service constraints are captured separately in [lead-gennie-mobile-prd.md](lead-gennie-mobile-prd.md); this document continues to describe the existing web MVP.

## Goal

Capture business cards and company documents, extract useful lead data, let a person verify and correct it, then save and export clean lead records.

## MVP scope

- React frontend, FastAPI backend, PostgreSQL storage.
- Camera capture, multiple-file upload, folder selection, and ZIP archives for scanned business documents.
- JPG, PNG, WebP, BMP, TIFF, GIF, and PDF scan formats.
- TXT raw-data preview with basic text parsing; CSV/XLSX preview finds recognized headers after leading blank/title rows and maps supported lead-field columns.
- Tabular imports map common aliases to Add Lead fields, including numeric Excel phone cells; unrelated spreadsheet columns are ignored.
- One candidate at a time in an editable review form. Multiple cards detected in a combined image are reviewed and saved sequentially.
- No automatic lead creation. The user checks the source and chooses **Save lead** for each candidate.
- Search, view, edit, delete, and export leads.
- List saved lead fields in matching, clearly named columns, including address; show each phone and email on its own line.
- Mobile-responsive controls and layout.
- A consistent enterprise-style visual system for navigation, lead tables, filters, forms, and details, with bold labels and accessible focus states.
- The navigation header displays the product brand without a local-workspace status label.
- The frontend API endpoint is configurable with `VITE_API_URL`; when local port 8000 conflicts with another service, set it to the scanner API on port 8001 and restart Vite. Local CORS defaults allow Vite ports 5173–5176 for both `localhost` and `127.0.0.1`; add custom ports to `CORS_ORIGINS`.

## Lead fields

| Field | Behavior |
|---|---|
| Autogenerated ID | Unique `LD-...` identifier generated on save. |
| Company name | Required; preserve the full legal name and suffix. |
| Owner name | Optional contact person. |
| Designation | Optional job title. |
| Address | One complete editable address field. |
| Contact numbers | Any number of values; each has an independent database row and export column. |
| Email addresses | Any number of values; each has an independent database row and export column. |
| Website | Optional. |
| Facebook / Instagram / WhatsApp | Optional structured profile/contact links; shown in web/mobile details and included in Excel export. |
| Other document text | Keep the full OCR/imported source text available to review and export. |
| Original OCR transcript | Preserve recognized source text separately when local Indic translation is used; available in details for audit. |

Any 10-digit contact number without a country prefix receives `+91` when saved, including numeric cells imported from Excel. Already prefixed `+91`/`91` values are not double-prefixed. Existing stored 10-digit values are normalized in list/detail responses and Excel exports too. Export writes normalized values as literal text so the prefix is preserved without an added apostrophe.

## User flow

1. Choose **Open camera**, **Upload files**, or **Choose folder**. ZIP archives can contain multiple card scans.
2. The API stores scanned sources and runs OCR. The UI shows progress and queues ready drafts. Raw TXT/CSV/XLSX rows are previewed without saving.
3. After upload, review the extracted/imported data on the preview form before saving. Review one card or spreadsheet row at a time, keep field-specific values in their own editable inputs, compare them with the source, correct mismatches, and confirm the review.
4. Choose **Save & continue** to insert the reviewed spreadsheet row and move directly to the next row in the same review screen, or choose **Generate remaining leads in one click** to create the remaining Excel rows as leads in one batch. Rows without a company name are skipped. Batch-generated rows are marked **Check data** until individually reviewed. The lead list refreshes after saves; nothing is stored until the user chooses a save action. Combined-image cards continue one by one.
5. Search/filter, view, edit, or delete saved leads from the lead workspace. Filters appear in this order: company name, owner name, state, city. Export selected leads or filtered results as XLSX, with an optional row count.

The scan queue is available as a compact action on the lead workspace and as a draft selector in the review screen. During a new upload, the selector and queue count are scoped to that upload batch, so selecting a folder with five supported images presents only those five documents; older pending drafts are not mixed into the batch. The review screen shows the uploaded image/PDF beside its editable fields, so the user can compare and correct the draft without opening another page or source tab. **Back to leads** returns to the list without clearing the current review form.

## Storage and export

- `leads` holds structured company/person/social fields, English/other-document text, original OCR transcript, verification state, and optional primary source document link.
- `lead_contacts` stores each phone and email separately with an order position, so there is no single concatenated contact field in the database.
- `lead_source_images` links one or more uploaded source images/documents to a saved lead, with front/back label and order; one two-sided card still creates one lead.
- XLSX export creates separate numbered phone and email columns up to the maximum values in the exported set. The header row is bold, white text on green fill; plain data cells use widths based on their contents, wrap long text, and receive readable row heights.
- The first column in both the leads list and XLSX export is a 1-based `S.No.`. List numbering continues across pages; filtered or selected export rows are numbered from 1 in their export order.
- Company and owner filters target their structured columns. State and city filters appear in that order and search within the one address field. An optional export count limits output to the newest matching rows; selected checkbox IDs override filters, and the count can limit the selected set.
- The server retains uploaded source documents in local private storage for review.

## Data-quality rules

- OCR and raw parsing produce candidates only; the user must review and save each record.
- Once card OCR completes, the review screen fetches the completed field values into the existing form. The draft remains uncommitted until the user confirms and saves it.
- Prefer company/legal-name markers and common business terms: estate/real estate, logistics, industries, technology/tech, pharmaceutical, limited, corporation, business, services, innovation, advertising, enterprises, solutions, spaces, hotel/lodge, groups, systems, restaurants, finance/loans, developers, associates, education, consultancy/consultant, society, movers/packagers, automation, hospital, NGO, institutes, and classes. Ignore keyword matches on lines that read like job titles. When Tesseract text layout is available, use the largest eligible non-person text line as a fallback company clue. Treat names beginning with Mr., Mrs., Ms., Miss, Dr., or Prof. as likely owners.
- Detect emails from `@` plus a valid domain, websites from domain/`www` patterns, and phone values including `+91` or `91` prefixes. Keep multiple values in separate form fields and database rows.
- Keep labeled source text as `Label: value` on one line. Raw spreadsheet columns remain separate, and a newly saved row is refreshed into the list before the next row is reviewed.
- For OCR documents, retain the full recognized source text. For CSV/XLSX imports, retain only values from recognized Add Lead columns, including an explicit Other Document Text column and clearly labeled company-description columns; ignore unrelated columns.
- Do not guess missing field values. Require the company name; let the user correct all other fields.
- Unstructured TXT and explicit Other Document Text values use simple patterns and cannot promise perfect categorization. CSV/XLSX rows map recognized lead-field headers and ignore unsupported columns. Keep user review mandatory.
- Address verification checks detected address lines first, then falls back to all OCR text if line detection split the address. The value still must match source words; users must compare it with the original card.
- Preserve phone/email order and deduplicate repeated identical values within a lead.

## Setup and scope

Run against a local PostgreSQL database configured in ignored `backend/.env`; run FastAPI and Vite separately. No Docker is required. Tesseract is used when installed; Windows can use its built-in OCR runtime as a fallback. Camera access requires browser support and permission, typically on localhost or HTTPS.

For a hosted backend, use `backend/Dockerfile` so the server installs the Tesseract executable and `eng`, `hin`, and `mar` language data. Configure hosted PostgreSQL and frontend-origin CORS values on the server; local Windows OCR and model paths are not valid in deployment. The M2M100 translation model remains an optional separate server installation.

If the hosted M2M100 model is unavailable, OCR review falls back to a Latin-only cleaned/transliterated transcript for field mapping. The original OCR transcript remains separate, and only structured fields are required to be Latin before saving.

This is a single-user local MVP without sign-in. Keep the API and source files off public networks. Avoid adding SaaS tenancy, enrichment, CRM integrations, team permissions, workflows, dashboards, or public share links until the basic lead flow is validated.
